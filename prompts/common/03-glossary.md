# Glossary

## Semantic-sort naming

Names are composed of ordered semantic components. Names sort naturally in alphabetical order. Names group related items together. Names encode structure. Names prevent drift.

## DELTA protocol

DELTA applies minimal corrections. DELTA keeps everything the same except the specified changes. DELTA does not regenerate full output. DELTA prevents drift. DELTA ensures determinism.

## Universal failure-prevention rules

Rules apply to all models. Rules prevent failure modes common in small models. Rules do not depend on model size. Rules do not require model self-awareness. Rules define naming, indentation, brace, sentence, and statement constraints.

## One-sentence-per-line

Each sentence occupies one line. Sentences must be short. Sentences must be clear. Sentences improve readability. Sentences improve diff clarity.

## One-statement-per-line

Each code statement occupies one line. Statements must be short. Statements must be clear. Statements improve readability. Statements prevent compression errors.

## Feature file

A file in prompts/features/. A file defining a project capability. A file describing requirements. A file describing behavior. A file used by the workflow.

## Plan block

A block listing ordered steps. A block using semantic-sort naming. A block using one sentence per line. A block preceding output. A block ensuring determinism.

## Output block

A block containing final output. A block following the plan. A block containing no commentary. A block following exact format. A block validated by universal rules.

## Context block

A block providing additional information. A block containing file contents. A block containing requirements. A block containing constraints. A block used only when needed.

## Scope-based identifier length

Short identifiers exist only in small scope. Large-scope identifiers require semantic-sort naming. Scope determines identifier length. Scope determines identifier clarity. Scope prevents naming drift.

## Ordered transformation pipeline

A sequence using o1, o2, o3. A sequence encoding transformation order. A sequence preventing ordering errors. A sequence improving clarity. A sequence used in web applications.

## Stability rules

Rules that never change. Rules that define project law. Rules that ensure determinism. Rules that prevent drift. Rules that apply to all tasks.
